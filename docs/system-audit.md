# Complete-game system audit

Verified on October 4, 2026 against [the acceptance contract](design-contract.md), which records the complete design brief and the later request for ranked ants, system branches, diagnostics, and generated play.

The game supports the complete loop: founding, excavation, economy, population, construction, individual combat, destruction, queen death, permanent purchases, and another colony. All simulation rules run in the headless engine. The interface submits orders and draws interpolated state.

## Generated gameplay

`npm run test:gameplay` runs 24 scenarios using seeds 23, 123, and 180231. Each scenario checks resource limits, living population and staff accounting, the unique queen, valid actor terrain, and finite diagnostic values. A save is restored every 37 simulated seconds. Each natural defeat checks that a reload cannot repeat its award, buys a permanent improvement, starts the next ant, and completes founding again.

All 24 scenarios passed, with 1,087 save round trips. Seven natural defeats completed the purchase and next-colony check. Later-lineage and permanent-improvement scenarios set only their starting permanent state; play still uses ordinary commands and earned resources. Test limits are observation limits, not game limits.

Compact results are committed in [verification-results.json](verification-results.json). The command regenerates detailed reports in `artifacts/gameplay-simulations.json` and `artifacts/gameplay-summary.json`, including counters, recent orders, samples, and raid plans. These large generated files stay outside Git.

The separate `npm run test:balance` command compares idle, economy, defended, and permanent-improvement policies over 40 minutes. Machine-specific timing results are recorded in [the work log](../BRANCHES.md).

## Interface and save workflow

Authorized checks used the local game preview. T3's browser tool was not available in this session, so the checks used the Codex in-app browser against the same local app.

- Desktop, tablet (768 pixels), and phone (390 pixels) layouts were inspected. No horizontal page overflow was found. Full-page images were captured and reviewed.
- Room selection, placement while paused, reserved food, cancellation refund, right-click excavation, and dig dragging worked through visible controls.
- Settings, export, valid import, invalid import, collection, permanent purchase, next colony, practice controls, practice defeat, and restore were exercised.
- An exported save was read with the engine and validated. Invalid imports kept the active colony and displayed a visible error in the modal.
- The defeat fixture came from ordinary simulated play. It showed the completed raid, peak population, cause, earned seeds, next ant, and purchase controls. The next colony displayed rank 49.
- Production verification and launch details are in [the work log](../BRANCHES.md).

## Scope and practical limits

The initial eight-enemy roster is complete for this release. The larger animal list in the brief was a design pool, so bosses, large multi-tile enemies, and other optional families are not implemented. All current ground enemies fit one tile. There is no offline progression, multiplayer, or second queen.

There is no fixed board boundary or population cap. Available memory and CPU still constrain a local browser. Tests include very distant terrain orders, 1,000 living ants, combat targeting equivalence, and later lineages. They do not prove unlimited performance or indefinite survival. Likewise, the roughly 15-minute opening is a balance target: the measured undefended runs last about 13.5 minutes, while deliberate defense lasts much longer.

No known failing requirement remains in the implemented scope after these checks. The source stays local, with no GitHub repository or deployment, as requested.
